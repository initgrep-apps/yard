# Manual signed in-app updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a manual, signed update check to the About dialog, with inline progress and a top-right toast fallback, without interrupting an active compression batch.

**Architecture:** A React `UpdateProvider` owns the updater state machine and wraps the shell inside `CompressionProvider`. The Tauri updater plugin performs the check/download/install; `tauri-action` signs release artifacts and generates `latest.json`. A preflight script blocks a release with a missing key or placeholder, and a post-build verifier blocks a draft whose manifest is incomplete.

**Tech Stack:** React 19, TypeScript, shadcn/base components, Sonner, Vitest, Tauri 2.12, `tauri-plugin-updater` 2.x, `tauri-plugin-process` 2.x, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-08-updater-design.md`

## Global Constraints

- Manual check only; never call `check()` on mount.
- All update copy says “the app”, never “Yard”. The About brand title remains “Yard”.
- Button labels: **Check for updates**, **Check again**, **Update now**, **Not now**, **Restart app**, **Try again**, **Download from GitHub**.
- Keep both MSI and NSIS installers and both macOS arches.
- Signing is mandatory. Do not generate, print, or commit the private key.
- The public key stays `REPLACE_WITH_UPDATER_PUBLIC_KEY` until the operator fills it.
- No automatic background checks, no delta updates, no custom update server.
- Follow existing project style: semantic tokens, Lucide icons, no code comments unless unavoidable.
- Run `yarn build && yarn test && (cd src-tauri && cargo test)` before the final commit.
- Run the Windows-target compile check from `docs/cicd-process.md` before pushing anything that touches `src-tauri/src/`.
- Commits use Conventional Commits.

## Review Focus

- **Active compression batch when download completes:** the app must enter Ready, never install or restart while `isCompressing` is true.
- **About closed during download:** progress must continue in a top-right toast; reopening About must dismiss the toast and show inline state.
- **Offline or GitHub unavailable:** check and download failures must be calm inline messages with retry, not unhandled rejections or endless spinners.
- **macOS read-only install path:** running from Downloads/translocation must produce an actionable install error, not a half-updated app.
- **Tampered or incomplete manifest:** missing platforms, empty signatures, wrong versions, or a signature that does not match the uploaded `.sig` must block the draft and be rejected by the app.

### Task 3: UpdateProvider state machine

**Files:**
- Create: `src/providers/UpdateProvider.tsx`
- Test: `src/providers/UpdateProvider.test.tsx`

**Interfaces:**
- Consumes: `useCompressionContext().isCompressing`, `usePlatform()`.
- Produces:

```ts
export type UpdateState =
  | { status: "idle" }
  | { status: "checking" }
  | { status: "current" }
  | { status: "available"; update: Update }
  | { status: "downloading"; update: Update; downloaded: number; total: number | null }
  | { status: "ready"; update: Update }
  | { status: "installing"; update: Update }
  | { status: "error"; stage: "check" | "download" | "install" | "relaunch"; message: string; update: Update | null };

export interface UpdateContextValue {
  state: UpdateState;
  canCheck: boolean;
  isCompressing: boolean;
  check: () => Promise<void>;
  startDownload: () => Promise<void>;
  install: () => Promise<void>;
  decline: () => Promise<void>;
  retry: () => Promise<void>;
  setSurfaceOpen: (open: boolean) => void;
}

export const UpdateContext: React.Context<UpdateContextValue | null>;
export function useUpdate(): UpdateContextValue;
export function UpdateProvider({ children }: { children: React.ReactNode });
```

- Error copy exactly:
  - check: `Couldn't check for updates. Check your connection and try again.`
  - download: `The update couldn't be downloaded. Check your connection and try again.`
  - install: `The update couldn't be installed. Try again, or download the latest installer from GitHub.`
  - install permission/path failure (macOS only): `The app couldn't be replaced. Move it to Applications, then try again.` Use this only when `platform === "darwin"` and the error text matches `/permission|denied|read-only/i`; otherwise use the generic install copy.
  - relaunch failure after a successful install: `The update was installed. Restart the app to finish.` Retry only `relaunch()`, never `install()` again.
- `check` calls `check({ timeout: 15_000 })`.
- `download` calls `update.download(onEvent, { timeout: 600_000 })`.
- `install` calls `update.install()`; call `relaunch()` only on `platform === "darwin"`.
- `decline` calls `update.close()` when an update is held, then sets idle.

  needs: [gate, release]

  permissions:
    contents: read
  timeout-minutes: 10
  steps:
    - name: checkout (v7.0.1)
      uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1

        gh release view "$RELEASE_TAG" --json assets > updater/assets.json
      shell: bash
    - name: verify manifest
      env:

      run: >-
        node scripts/ci/verify-updater-manifest.mjs

      shell: bash
